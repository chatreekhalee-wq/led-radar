# LED Radar — ระบบคัดทรัพย์ขายทอดตลาดกรมบังคับคดี

ระบบนี้ไม่ต้องมีเซิร์ฟเวอร์ ใช้ของฟรี 3 อย่าง

| ส่วน | ทำงานที่ | หน้าที่ |
|---|---|---|
| ปุ่ม “เก็บทรัพย์ LED” | Chrome ของคุณ | กดบนหน้าที่เปิดดูอยู่ ส่งข้อมูลหน้านั้นเข้าฐานข้อมูล |
| ฐานข้อมูล | Supabase (ฟรี) | เก็บข้อมูลดิบ ทรัพย์ นัดขาย คะแนน โน้ต |
| ตัวประมวลผล | GitHub Actions (ฟรี ทุก 3 ชม.) | แยกข้อมูล → คิดราคาแต่ละนัด → หาพิกัด → วัดทำเล → ให้คะแนน → แจ้งเตือน Telegram |
| Dashboard | GitHub Pages (ฟรี) | แผนที่ ตาราง ตัวกรอง ปรับน้ำหนัก เครื่องคิดต้นทุน watchlist |

> ทำไมไม่ดึงข้อมูลอัตโนมัติ: เว็บ asset.led.go.th ระบุไม่อนุญาตให้บอตเข้าถึง ระบบนี้จึงเก็บเฉพาะหน้าที่คุณเปิดดูเองแล้วกดปุ่ม
> ถ้ากรมบังคับคดีอนุญาตหรือเปิด API ให้ (ดู `docs/request-letter.md`) ค่อยเพิ่มตัวดึงอัตโนมัติภายหลังได้ ส่วนอื่นใช้ต่อได้ทั้งหมด

## ติดตั้ง (ราว 30 นาที ครั้งเดียว)

### 1. Supabase
1. สมัคร https://supabase.com → New project (เลือก region Singapore)
2. เมนู **SQL Editor** → วางไฟล์ `supabase/schema.sql` ทั้งไฟล์ → Run
3. รันอีกครั้งเฉพาะ 2 บรรทัดนี้ (แก้ค่าก่อน):
   ```sql
   insert into app_secrets(key, value) values ('capture_token', 'ตั้งรหัสยาวๆ เอง เช่น 32 ตัวอักษร');
   insert into app_admins(email) values ('อีเมลของคุณ');
   ```
4. **Authentication → Users → Add user** ใส่อีเมลเดียวกัน (ใช้ล็อกอิน Dashboard เพื่อบันทึกโน้ต)
5. **Authentication → URL Configuration** ใส่ Site URL = ลิงก์ GitHub Pages ของคุณ (ได้จากขั้นที่ 2)
6. **Project Settings → API** จดไว้ 3 ค่า: Project URL, `anon` key, `service_role` key (ห้ามเปิดเผย service_role)

### 2. GitHub
1. สร้าง repo ใหม่ (Private ได้) แล้วอัปโหลดไฟล์ทั้งโฟลเดอร์นี้
2. **Settings → Secrets and variables → Actions**
   - แท็บ *Secrets*: `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` (= service_role), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`
   - แท็บ *Variables*: `SUPABASE_URL_PUBLIC` (= Project URL), `SUPABASE_ANON_KEY` (= anon), `DASHBOARD_URL` (ลิงก์ Pages), `OSM_USER_AGENT` (เช่น `LED-Radar/1.0 (อีเมลของคุณ)`)
3. **Settings → Pages → Source = GitHub Actions**
4. **Actions → LED Radar pipeline → Run workflow** หนึ่งครั้ง ได้ทั้ง Dashboard และรอบประมวลผลแรก
   - repo แบบ Private: GitHub Pages ใช้ได้เฉพาะแพ็กเกจที่รองรับ ถ้าใช้ไม่ได้ให้ตั้ง repo เป็น Public (ข้อมูลลับอยู่ใน Secrets ไม่อยู่ในโค้ด) หรือใช้ Cloudflare Pages ชี้โฟลเดอร์ `site/` แทน

### 3. Telegram (แจ้งเตือน)
1. คุยกับ `@BotFather` → `/newbot` → ได้ token
2. ทักบอตของคุณหนึ่งครั้ง แล้วเปิด `https://api.telegram.org/bot<TOKEN>/getUpdates` ดู `chat.id`
3. ใส่ทั้งสองค่าใน GitHub Secrets

### 4. ปุ่มเก็บข้อมูล
1. เปิด `<ลิงก์ Pages>/install.html`
2. กรอก Project URL, anon key, capture_token → กด **สร้างปุ่ม** → ลากปุ่มไปไว้บนแถบบุ๊กมาร์ก

## ใช้งานประจำวัน
1. เปิดเว็บค้นหาทรัพย์ของกรมบังคับคดี ค้นตามจังหวัด/ประเภทที่สนใจ
2. กดปุ่ม **📥 เก็บทรัพย์ LED** ทีละหน้าผลค้นหา (หน้ารายละเอียดทรัพย์ได้ข้อมูลครบกว่า เช่น ราคากรมธนารักษ์ เงื่อนไขการขาย)
3. ภายใน 3 ชั่วโมง ระบบคิดคะแนนเสร็จ หรือกด Run workflow เพื่อดูทันที
4. เปิด Dashboard เลือกเป้าหมาย (ปล่อยเช่า / รีโนเวทขาย / ที่ดิน) แล้วไล่ดูจากคะแนนสูงสุด
5. ทรัพย์ที่สนใจ: กด ★ ติดตาม ใส่พิกัดจริงจาก LandsMaps และจดผลการลงพื้นที่

## คะแนนคิดอย่างไร
คะแนนย่อย 0–100 (ไม่มีข้อมูล = 50)
- **ส่วนลด**: ราคาเริ่มนัดถัดไป ÷ ราคาประเมินเจ้าพนักงาน (นัด 1 = 100%, นัด 2 = 90%, นัด 3 = 80%, นัด 4 ขึ้นไป = 70%) แก้ได้ที่ `round_price_pct`
- **ราคาต่อหน่วย**: บาท/ตร.วา (หรือ ตร.ม. สำหรับห้องชุด) ของราคาประเมิน เทียบค่ากลางของอำเภอและประเภทเดียวกันจากข้อมูลที่เก็บไว้ (ต้องมีอย่างน้อย 4 รายการ)
- **ทำเล**: ระยะถึงถนนสายหลัก ตลาด/ห้าง โรงเรียน โรงพยาบาล สถานี นิคมอุตสาหกรรม และความหนาแน่นรอบแปลง จาก OpenStreetMap มี 3 สูตรตามเป้าหมาย พิกัดระดับตำบลจะถูกดึงเข้าหา 50 เพราะยังไม่แน่นอน
- **คู่แข่งน้อย**: จำนวนนัดที่ผ่านไปโดยไม่มีผู้ซื้อ
- **หักความเสี่ยง**: คำในประกาศ เช่น ขายเฉพาะส่วน ไม่มีทางเข้าออก ติดจำนอง ส.ป.ก. มีผู้อาศัย (แก้รายการคำได้ที่ `risk_keywords` ใน `worker/config.json`)

## เมื่อเว็บกรมบังคับคดีเปลี่ยนหน้าตา
ข้อมูลดิบทั้งหน้าถูกเก็บไว้ใน `raw_captures` เสมอ ถ้า parse ไม่ได้ สถานะจะเป็น `error`
1. ดูข้อมูลดิบที่ error ใน Supabase → Table editor → raw_captures
2. ปรับ `HEADER_MAP` หรือ `DETAIL_PATTERNS` ใน `worker/parse_led.py` (เพิ่มตัวอย่างใน `tests/fixtures` แล้วรัน `pytest`)
3. Run workflow โดยติ๊ก **reparse** ระบบจะ parse ข้อมูลเก่าทั้งหมดใหม่ ไม่ต้องเก็บซ้ำ

## โครงสร้าง
```
supabase/schema.sql        ตาราง, view, สิทธิ์ (RLS), ฟังก์ชันรับข้อมูลจากปุ่ม
bookmarklet/               ปุ่มเก็บข้อมูล + หน้าติดตั้ง
worker/                    parse → rounds → geo → score → alerts (Python)
  config.json              น้ำหนักคะแนน, % ราคาแต่ละนัด, คำเสี่ยง, เกณฑ์แจ้งเตือน
dashboard/index.html       หน้า Dashboard (ไม่มีข้อมูล Supabase = โหมดข้อมูลตัวอย่าง)
tests/                     ทดสอบ parser, คะแนน และทั้งเส้นด้วยฐานข้อมูลจำลอง
.github/workflows/         รันทุก 3 ชม. + deploy Pages
docs/request-letter.md     ร่างหนังสือขอข้อมูลจากกรมบังคับคดี
```

## ข้อควรรู้
- คะแนนเป็นตัวช่วยคัด ไม่ใช่คำแนะนำการลงทุน ทรัพย์บังคับคดีขายตามสภาพ ต้องตรวจโฉนด ลงพื้นที่ และอ่านประกาศฉบับเต็มทุกครั้ง
- ระบบเรียก Nominatim/Overpass ของ OpenStreetMap แบบสุภาพ (1 ครั้ง/วินาที, จำกัด 40 แปลงต่อรอบ, แคชผล)
- ข้อมูลใน Dashboard อ่านได้ด้วย anon key (เป็นข้อมูลประกาศสาธารณะ) ส่วนโน้ตและ watchlist เห็นได้เฉพาะอีเมลใน `app_admins`
